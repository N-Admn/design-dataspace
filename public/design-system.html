Foundations — Iconography

lucide-react
PropertyValue
Librarylucide-react — every icon import in src/components comes from this package; no custom SVG icon set exists.
Default sizeButton icons default to size-4 (16px) via the button's own [&_svg]:size-4 rule; standalone icons are sized explicitly per context (size-3.5 to size-5 depending on density).
StrokeDefault lucide stroke-width (2), except small inline checkmarks which use strokeWidth={3} for legibility at 12px (Checkbox, Stepper "done" icon).
ColorIcons inherit currentColor — never hardcoded, so they always match the surrounding text/button color in both themes.

asChildbooleanfalseRenders via Radix Slot onto its child element instead of a <button>.
...propsReact.ComponentProps<'button'>—All native button attributes (disabled, onClick, type, aria-*) pass through.

Usage guidelines

Do
One default button per screen for the primary action the user came to do.
Don't
Use two default buttons side by side — demote the secondary action to outline or secondary.

Accessibility

  • Focus-visible ring (2px, --ring color, 2px offset) on every variant — never suppressed.
  • Renders a real <button> (or Slot target), so native disabled/keyboard/screen-reader semantics come for free — no custom ARIA needed.
  • Icon-only buttons must set aria-label manually — the component doesn't enforce this.

Code

import { Button } from '@/components/ui/button' import { Send } from 'lucide-react' <Button variant="default" size="lg" onClick={handlePublish}> Publish Dataset <Send className="size-4" /> </Button>

Accessibility

Standard followed

WCAG 2.1 Level AA is the target — reflected in the contrast thresholds used throughout this site (4.5:1 normal text, 3:1 large text/UI components) and in the components' reliance on Radix UI primitives, which ship keyboard and ARIA behavior by default rather than reimplementing it.

Global rules

RuleStatus in code
Touch targets ≥ 44×44pxDefault buttons (40px) and icon buttons (36×36px) fall slightly under the 44px guideline. Acceptable in dense desktop tables with adequate row spacing; a real gap on touch layouts — flagged, not yet fixed.
Focus visibilityEvery interactive primitive shows a 2px focus-visible ring — never suppressed with outline-none alone.
Reduced motionNot globally guarded in the app's own CSS — inherited only where an artifact-style prefers-reduced-motion block exists. Toast/dialog animations use Tailwind's animate-in/animate-out utilities.
Color contrastBrand navy-on-white and white-on-navy both pass AA comfortably; verify any new token pairing with the contrast badges in Foundations → Color before shipping.
Chart color-blind safetyThe 5-step chart palette is a single-hue warm ramp — safe for sequential/ordered data under all common color-vision deficiencies, but does not provide enough hue separation for unordered categorical series.

Voice & Content

Tone

Direct, active voice. A control says exactly what happens ("Publish", then a toast that says "Published"). Errors state what's wrong and how to fix it — never an apology, never "Invalid input."
